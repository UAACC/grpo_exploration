# Local Setup Guide: What's Missing After Copying backup_dongheng

This document lists everything that exists OUTSIDE of the `backup_dongheng/` folder but is required to run the code. After copying this folder to a local machine, you need to address each item below.

---

## 1. Models (NOT included)

The code references two models via hardcoded snapshot paths on the cluster:

| Model | HuggingFace ID | Size | Used For |
|---|---|---|---|
| Student | `Qwen/Qwen2.5-0.5B-Instruct` | ~1GB | Training target |
| Teacher | `Qwen/Qwen2.5-Math-7B-Instruct` | ~15GB | Rollout generation |

**Cluster paths** (in all `run_*.sh` files):
```
STUDENT_DIR="${HF_CACHE}/models--Qwen--Qwen2.5-0.5B-Instruct/snapshots/7ae557604adf67be50417f59c2c2f167def9a775"
TEACHER_DIR="${HF_CACHE}/models--Qwen--Qwen2.5-Math-7B-Instruct/snapshots/ef9926d75ab1d54532f6a30dd5e760355eb9aa4d"
```

**To fix locally:**
```bash
# Option A: Download from HuggingFace (needs internet + disk space)
pip install huggingface_hub
huggingface-cli download Qwen/Qwen2.5-0.5B-Instruct
huggingface-cli download Qwen/Qwen2.5-Math-7B-Instruct

# Option B: Just use the HF model IDs directly (if you have internet)
# Change shell scripts:
STUDENT_DIR="Qwen/Qwen2.5-0.5B-Instruct"
TEACHER_DIR="Qwen/Qwen2.5-Math-7B-Instruct"
```

**Files to update:** Every `run_*.sh` in `offline_grpo/`, `online_grpo/`, `mixture_grpo/`

**Also hardcoded in Python files:**
- `offline_grpo/configs.py` line 20-21: `DEFAULT_TARGET_MODEL` and `DEFAULT_BEHAVIOR_MODEL` (these use HF IDs, so they work online — only the shell scripts use full paths)
- `offline_grpo/diagnose.py` line 9: hardcoded snapshot path
- `online_grpo/check_baseline_output.py` line 5: hardcoded snapshot path

## 3. Pre-generated Rollout Files (NOT included)

These JSONL files contain teacher-generated completions with per-token logprobs. They are stored on scratch disk and are **required for offline/mixture training**.

| File | Size | Used By |
|---|---|---|
| `/home/mrli/scratch/dongheng/gsm8k_teacher_rollouts/rollouts_gsm8k.jsonl` | ~500MB | mixture_grpo (Method A & B) |
| `/home/mrli/scratch/dongheng/gsm8k_offline_rollouts/rollouts_gsm8k.jsonl` | ~500MB | offline_grpo (GSM8K) |
| `/home/mrli/scratch/rollouts_qwen2.5_math_7b_instruct_temp0.6_3_flatten.jsonl` | ~2GB | offline_grpo (MATH) |

**To fix locally:**
```bash
# Regenerate rollouts (requires teacher model + GPU)
# GSM8K:
python generate_rollouts.py \
    --model_name Qwen/Qwen2.5-Math-7B-Instruct \
    --dataset_type gsm8k \
    --num_generations 4 \
    --temperature 0.7 \
    --output_path ./rollouts_gsm8k.jsonl

# Then update ROLLOUT_PATH in run_*.sh
```

**Note:** Generating rollouts requires the 7B teacher model and a GPU with ~16GB+ VRAM. This is the most compute-intensive prerequisite.

## 7. SLURM / Cluster-Specific Configuration

These items only apply to the Vulcan HPC cluster and need conversion for local use:

### 7a. SBATCH Headers
Every `run_*.sh` has SLURM headers like:
```bash
#SBATCH --account=aip-szepesva
#SBATCH --time=12:00:00
#SBATCH --gpus-per-node=l40s:4
#SBATCH --cpus-per-task=64
#SBATCH --mem=256G
```
**Locally:** Remove these headers. Run scripts directly with `bash` instead of `sbatch`.

### 7b. Module System
```bash
module load python/3.11 cuda/12.6
```
**Locally:** Remove these lines. Ensure Python 3.11+ and CUDA are installed system-wide.

### 7c. Accelerate Configs
Files in `offline_grpo/configs/`:
- `accelerate_ddp_4gpu.yaml` — assumes 4 GPUs
- `accelerate_ddp_2gpu.yaml` — assumes 2 GPUs
- `accelerate_zero2_4gpu.yaml` — DeepSpeed ZeRO-2

**Locally:** Create configs matching your GPU count:
```bash
accelerate config  # interactive setup
# Or edit yaml: change num_processes to your GPU count
```

### 7d. Log Directories
```bash
#SBATCH --output=logs/mixture_A/%x-%j.out
#SBATCH --error=logs/mixture_A/%x-%j.err
```
**Locally:** Redirect stdout/stderr manually or just run in terminal.

## 9. GPU Requirements

| Task | Minimum GPU | Recommended |
|---|---|---|
| Generate rollouts (7B teacher) | 1× 16GB | 1× 24GB+ |
| Train offline GRPO (0.5B student) | 1× 12GB | 4× L40s (48GB) |
| Train mixture GRPO (0.5B + generation) | 4× 24GB | 4× L40s (48GB) |
| Evaluate (0.5B merged) | 1× 8GB | 1× 16GB+ |

**Without a GPU:** You can still read and understand all the code, but cannot run training or generation.

## 10. Quick-Start Checklist

To get the code running locally, do these in order:

```
□ 1. Install Python 3.11+ and CUDA 12.x
□ 2. Create virtual environment and install dependencies (Section 5)
□ 3. Download models (Section 1) — at minimum the 0.5B student
□ 4. Download datasets (Section 2) — or remove offline mode
□ 5. Create/update WandB key (Section 6) — or disable wandb
□ 6. Update all hardcoded paths in run_*.sh (Section 8)
□ 7. Remove SLURM headers and module loads from run_*.sh (Section 7)
□ 8. Create accelerate config matching your GPU count (Section 7c)
□ 9. Generate rollouts if doing offline/mixture training (Section 3)
□ 10. Run training!
```
