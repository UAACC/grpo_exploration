# GRPO Formulation: From Equations to Code

Every symbol in the math maps to a specific line of code, a specific tensor, or a specific file. This document makes that mapping explicit.

---

## The Players

Before any equations, let's name the three models involved:

| Symbol | What it is | Our model | Where it lives |
|--------|-----------|-----------|----------------|
| π_β | **Behavior policy** — generated the solutions | Qwen2.5-Math-7B-Instruct (teacher) | Only at rollout time. During training, its logprobs are read from `rollouts_full.jsonl` |
| π_θ | **Target policy** — being trained | Qwen2.5-0.5B-Instruct + LoRA (student) | Loaded in `train.py:81-86`, forward pass in TRL's `_compute_loss` |
| π_ref | **Reference policy** — anchor for KL penalty | Qwen2.5-0.5B-Instruct without LoRA (student's initial weights) | Same model with `disable_adapter()`, `trainer.py:148` |

π_β and π_ref are **different models**. π_β is the 7B teacher. π_ref is the 0.5B student before any LoRA updates. They serve different roles in the loss.

## Stage 1: Reward

For each completion o generated by the teacher for prompt q:

```
r(o) = { 2.0   if math_verify(extract_boxed(o), ground_truth) = True
        { 0.0   otherwise
```

**Code**: `data.py:69-76`
```python
def _compute_correctness(extracted, ground_truth):
    if verify(parse(extracted), parse(ground_truth)) is True:
        return 2.0
    return 0.0
```

This is computed once, offline, for all 48,000 completions. The number 2.0 vs 0.0 is arbitrary — what matters is the difference between correct and incorrect within a group.

## Stage 2: Group-Relative Advantage

For prompt q_j with G completions {o_{j,1}, ..., o_{j,G}}, each with reward r_{j,i}:

```
         r_{j,i} - μ_j
A_{j,i} = ─────────────
            σ_j + ε
```

where:

```
        1   G
μ_j  =  ─  Σ  r_{j,i}          (group mean)
        G  i=1

             ┌  1   G                    ┐
σ_j  =  sqrt│  ─  Σ  (r_{j,i} - μ_j)²  │   (group std, population)
             └  G  i=1                    ┘

ε = 1e-4                        (prevents division by zero)
```

**Code**: `data.py:95-100`
```python
for group in groups.values():                          # for each prompt q_j
    rewards = [r["reward"] for r in group]             # {r_{j,1}, ..., r_{j,G}}
    mean_r = sum(rewards) / len(rewards)               # μ_j
    std_r = (sum((r - mean_r)**2 for r in rewards)     # σ_j
             / len(rewards)) ** 0.5
    for rec in group:
        rec["advantage"] = (rec["reward"] - mean_r)    # A_{j,i}
                           / (std_r + eps)
```

**What each piece does**:

- **μ_j** (group mean): Establishes the baseline for this specific problem. "On this problem, the teacher scored 1.5 on average." Without this, we'd be comparing rewards across problems of different difficulty.

- **σ_j** (group std): Normalizes the scale. A group with rewards [2, 2, 0, 0] and a group with rewards [2, 0, 0, 0] have different spreads. Dividing by std makes advantages comparable: ±1.0 for the first, +1.73/-0.58 for the second.

- **ε**: When all rewards are identical (σ_j = 0), the advantage becomes 0/ε ≈ 0. This correctly produces zero gradient — no contrast means no signal.

- **A_{j,i}**: The final advantage. Positive means "better than group average" → push student toward this. Negative means "worse than group average" → push student away. Zero means "exactly average" or "no variation" → no gradient.

The advantage is a **scalar per completion** — one number that applies to the entire token sequence. It does not vary across tokens within a completion.

**Code (entering the trainer)**: `trainer.py:91` loads the pre-computed advantage, and `trainer.py:129` packs it into a tensor:
```python
advantages_list.append(rec["advantage"])               # looked up from offline_data
advantages = torch.tensor(advantages_list, ...)        # shape: (B,)
```

## Stage 3: Per-Token Log-Probabilities

For each token position t in completion o_{j,i}, we need log-probabilities from three policies.

### 3a. Behavior policy logprobs: log π_β(o_t | q, o_{<t})

These are the teacher's per-token logprobs, recorded during rollout generation.

**Generated in**: `generate_rollouts.py:118-122`
```python
for step, tid in enumerate(token_ids):
    lp_dict = step_logprobs[step]           # vLLM gives {token_id: Logprob}
    lp_obj = lp_dict.get(tid, None)
    logprob_list.append(float(lp_obj.logprob))  # log π_β(o_t | q, o_{<t})
```

**Loaded in trainer**: `trainer.py:90` and packed into tensor at `trainer.py:128`:
```python
behavior_logprob_lists.append(rec["behavior_logprobs"])  # list of floats
old_per_token_logps = torch.stack(old_logps_tensors)     # shape: (B, T)
```

The variable name `old_per_token_logps` is TRL's convention from online GRPO where "old" means the previous iteration's policy. In our offline setting, "old" = behavior policy = teacher.

### 3b. Target policy logprobs: log π_θ(o_t | q, o_{<t})

These are the student's logprobs for the teacher's tokens, computed fresh every training step via forward pass.

**Code**: `grpo_trainer.py:1827-1837` (TRL's `_compute_loss`)
```python
per_token_logps, entropies = self._get_per_token_logps_and_entropies(
    model,                  # π_θ (student with LoRA)
    input_ids,              # [prompt_ids | completion_ids]
    attention_mask,
    logits_to_keep,         # only compute logps for completion tokens
    compute_entropy=True,
)
```

The student feeds in [prompt + teacher's completion] in one forward pass. The causal mask ensures each position only sees tokens before it, so the logprob at position t is exactly `log π_θ(o_t | q, o_{<t})`.

This is the **only forward pass that produces gradients**. Everything else is either pre-computed or computed under `torch.no_grad()`.

Result: `per_token_logps` — shape (B, T), the student's log-probability for each of the teacher's tokens.

### 3c. Reference policy logprobs: log π_ref(o_t | q, o_{<t})

These are the student's base model logprobs (without LoRA), computed every step for the KL penalty.

**Code**: `trainer.py:147-154`
```python
with self.accelerator.unwrap_model(self.model).disable_adapter():
    ref_per_token_logps, _ = self._get_per_token_logps_and_entropies(
        self.model,         # same model, but LoRA adapter disabled → π_ref
        prompt_completion_ids,
        attention_mask,
        logits_to_keep,
    )
```

`disable_adapter()` temporarily turns off all LoRA layers, so the model behaves as its pre-training self. This is computed under `torch.no_grad()` — no gradients flow through the reference.

Result: `ref_per_token_logps` — shape (B, T).

## Stage 4: Importance Sampling Ratio

The ratio corrects for the distribution mismatch between who generated the completions (teacher) and who is learning (student):

```
                   π_θ(o_t | q, o_{<t})
ρ_t = ────────────────────────────────────
                   π_β(o_t | q, o_{<t})
```

In log-space (numerically stable):

```
log ρ_t = log π_θ(o_t | q, o_{<t}) - log π_β(o_t | q, o_{<t})
```

**Code**: `grpo_trainer.py:1859`
```python
log_ratio = per_token_logps - old_per_token_logps
#           ^^^^^^^^^^^^^^^^   ^^^^^^^^^^^^^^^^^^^^
#           log π_θ (3b)       log π_β (3a)
```

Then exponentiate: `grpo_trainer.py:1873`
```python
coef_1 = torch.exp(log_importance_weights)    # ρ_t = exp(log ρ_t)
```

**What the ratio means per token**:
- ρ_t > 1: Student thinks this token is **more** likely than teacher did → amplifies gradient
- ρ_t < 1: Student thinks this token is **less** likely than teacher did → dampens gradient
- ρ_t = 1: Student and teacher agree on this token's probability → gradient passes through unchanged

**Why it matters**: Without the ratio, the gradient would treat all of the teacher's tokens equally. But the student is a different model — some of the teacher's tokens are natural for the student, others are foreign. The ratio scales the gradient by "how much does the student already agree with this token?" This is the importance sampling correction that makes off-policy learning valid.

### Importance sampling level

TRL supports two modes (`grpo_trainer.py:1860-1864`):

- **Token level** (default, ours): each token gets its own ratio ρ_t. Shape: (B, T).
- **Sequence level**: average the log-ratio across all tokens in the completion, then exponentiate. One ratio per completion. Shape: (B, 1).

We use token-level, so the clipping and loss operate per-token.

---

## Stage 5: Clipping

The ratio is clipped to prevent extreme updates:

```
ρ̃_t = clip(ρ_t, 1 - ε_low, 1 + ε_high)
```

In TRL, `ε_low` and `ε_high` both default to `epsilon` (which defaults to 0.2 in GRPOConfig):

**Code**: `grpo_trainer.py:1874`
```python
coef_2 = torch.clamp(coef_1, 1 - self.epsilon_low, 1 + self.epsilon_high)
#                             ^^^^^^^^^^^^^^^^^^^^   ^^^^^^^^^^^^^^^^^^^^^
#                             0.8                     1.2
```

**Why clipping matters especially in offline GRPO**:

In online GRPO, the ratio starts near 1.0 because completions were just generated by a recent version of the same model. In our offline setting, the ratio starts far from 1.0 because π_θ (0.5B student) and π_β (7B teacher) are fundamentally different models. Without clipping, a few tokens where the student wildly disagrees with the teacher (ρ = 50 or ρ = 0.001) would dominate the loss.

---

## Stage 6: Per-Token Policy Loss

The PPO-style clipped surrogate objective, applied per-token:

```
L^policy_t = -min(ρ_t · A, ρ̃_t · A)
```

where A is the completion-level advantage (same value for every token in the completion).

**Code**: `grpo_trainer.py:1880-1882`
```python
per_token_loss1 = coef_1 * advantages.unsqueeze(1)     # ρ_t · A
per_token_loss2 = coef_2 * advantages.unsqueeze(1)     # ρ̃_t · A
per_token_loss = -torch.min(per_token_loss1, per_token_loss2)  # -min(...)
```

`advantages.unsqueeze(1)` broadcasts the scalar advantage A_{j,i} across all T token positions.

**How the min + negation works**:

Case 1: **Positive advantage** (A > 0, correct solution, "be more like this")
- ρ_t · A and ρ̃_t · A are both positive
- `min(...)` picks the smaller one
- If ρ_t > 1.2 (student already likes this token more than teacher): clipped ratio is used → limits how much gradient flows. Prevents "over-reinforcing" tokens the student already favors.
- If ρ_t < 1.2: unclipped ratio is used → full gradient.
- `-min(...)` is negative → gradient descent pushes loss down → student logprob goes UP

Case 2: **Negative advantage** (A < 0, wrong solution, "be less like this")
- ρ_t · A and ρ̃_t · A are both negative
- `min(...)` picks the more negative one (larger magnitude)
- If ρ_t < 0.8 (student already dislikes this token): clipped ratio is used → limits how much gradient flows. Prevents "over-punishing" tokens the student already avoids.
- If ρ_t > 0.8: unclipped ratio is used → full gradient.
- `-min(...)` is positive → gradient descent pushes loss down → student logprob goes DOWN

Case 3: **Zero advantage** (A = 0, all-same group)
- Both products are 0
- `-min(0, 0)` = 0
- No gradient. The student learns nothing from this completion.

## Stage 7: KL Penalty

The KL divergence prevents the student from drifting too far from its initial (pre-LoRA) weights:

```
KL_t = exp(log π_ref(o_t) - log π_θ(o_t)) - (log π_ref(o_t) - log π_θ(o_t)) - 1
```

This is the Schulman KL estimator. Properties:
- Always ≥ 0
- Equals 0 when π_θ = π_ref (student hasn't changed from base)
- Grows as π_θ diverges from π_ref in either direction

**Code**: `grpo_trainer.py:1847-1849`
```python
per_token_kl = (
    torch.exp(ref_per_token_logps - per_token_logps)     # exp(log π_ref - log π_θ)
    - (ref_per_token_logps - per_token_logps)             # - (log π_ref - log π_θ)
    - 1                                                    # - 1
)
```

**Note**: The KL is between π_θ and π_ref (student vs student-base), NOT between π_θ and π_β (student vs teacher). The teacher's logprobs only appear in the IS ratio, not in the KL penalty. The KL penalty asks: "how far has the student moved from where it started?" not "how far is the student from the teacher?"

---

## Stage 8: Total Per-Token Loss

Combine the policy loss and KL penalty:

```
L_t = L^policy_t + β · KL_t
```

```
    = -min(ρ_t · A, ρ̃_t · A) + β · KL_t
```

**Code**: `grpo_trainer.py:1885-1886`
```python
if self.beta != 0.0:
    per_token_loss = per_token_loss + self.beta * per_token_kl
#                    ^^^^^^^^^^^^^   ^^^^^^^^^^^^^^^^^^^^^^^^^^^^
#                    L^policy_t       β · KL_t
```

β = 0.1 in our experiment (`train.py:35`).

---

## Stage 9: Aggregation to Scalar Loss

Average across tokens (masked), then across completions in the batch:

```
              1    B   ┌  1     T                          ┐
L(θ)  =      ─   Σ    │  ──   Σ  L_t · mask_t             │
              B   j=1  └  T_j  t=1                         ┘
```

where T_j is the number of non-padding tokens in completion j, and mask_t is 1 for real tokens and 0 for padding.

**Code**: `grpo_trainer.py:1888-1889`
```python
if self.loss_type == "grpo":
    loss = ((per_token_loss * completion_mask).sum(-1)    # sum over tokens (masked)
            / completion_mask.sum(-1).clamp(min=1.0)      # divide by T_j (per-completion mean)
           ).mean()                                        # mean over batch
```

This scalar `loss` is what `.backward()` is called on. Gradients flow through `per_token_logps` (the only quantity computed with gradients enabled) into the LoRA parameters.

## The Complete Picture

Putting all 9 stages together, the full loss for one completion (o_{j,i}) of prompt q_j:

```
              1    T
L_{j,i}  =   ──   Σ   [ -min(ρ_t · A_{j,i},  clip(ρ_t, 0.8, 1.2) · A_{j,i})  +  β · KL_t ]
              T_j  t=1
```

where:

```
                r_{j,i} - μ_j
A_{j,i}  =     ─────────────             advantage (data.py:100)
                  σ_j + ε

             π_θ(o_t | q_j, o_{<t})
ρ_t     =   ──────────────────────        IS ratio (grpo_trainer.py:1859,1873)
             π_β(o_t | q_j, o_{<t})

KL_t    =   exp(log π_ref - log π_θ)     Schulman KL (grpo_trainer.py:1847-1849)
             - (log π_ref - log π_θ)
             - 1
```

And the batch loss:

```
              1
L(θ)  =      ─    Σ      L_{j,i}          (grpo_trainer.py:1889)
              B   (j,i)
```

Gradient descent minimizes L(θ) by updating only the LoRA parameters in π_θ.
