# Progress Report: April 14, 2026

## Summary

The biggest effort this period went into building a unified dataset infrastructure: refactoring every training script in the codebase (online GRPO, Mixture A, Mixture B, DG-offline, DG-Mixture, BC) so that adding a new dataset requires only a single registry entry, with zero training script changes. This wasn't technically difficult but involved tracing dataset-specific logic through 9 files and replacing it with registry lookups, fixing a teacher answer format bug along the way. With that in place, we generated teacher rollouts and kicked off training on SVAMP and ASDiv to test whether our MATH and GSM8K findings generalize to other benchmarks. We also started the two-stage "DG-offline then online GRPO" experiment that Alex suggested.

## 1. Unified Dataset Infrastructure (Main Engineering Effort)

### The problem

Every training script had hardcoded `if dataset_type == "math": ... else: ...` branches: dataset-specific HF paths, field names, system prompts, answer extraction functions, and reward functions. Adding SVAMP meant touching `online_grpo/train.py`, all three mixture trainers, both data loaders, and the eval scripts. Each file had its own copy of the branching logic.

### What we built

`shared/datasets_registry.py`: a single module where each dataset is defined once with all its metadata. Training scripts import from the registry instead of hardcoding anything.

```python
cfg = get_dataset_config("svamp")   # or "math", "gsm8k", "asdiv"
# cfg.hf_path, cfg.question_field, cfg.system_prompt, cfg.reward_func, cfg.check_answer, ...
```

Adding a new dataset to the entire pipeline (training + eval + rollout generation) is now:

1. Add one entry to `datasets_registry.py` (~15 lines)
2. Download to scratch cache
3. Generate rollouts: `DATASET=new sbatch shared/run_generate_rollouts.sh`
4. Train any method: `METHOD=bc DATASET=new sbatch shared/run_train_offline.sh`
5. Eval: `DATASET=new MODEL=/path sbatch shared/run_eval.sh`

No training script changes needed for future datasets.

### What got modified

9 files touched to replace dataset-specific logic with registry imports:

| Script | What changed |
|--------|-------------|

### Bug found: teacher answer format mismatch

When generating SVAMP rollouts, the teacher accuracy came back at 14%. The teacher was clearly getting correct answers, but our `extract_numeric_answer` looked for `####` and the 7B Math teacher outputs `\boxed{145}` even on elementary numeric problems.

Fix: `extract_numeric_answer` now tries three extraction methods in order: (1) `####` delimiter, (2) `\boxed{}`, (3) last number in text. Same fix applied to `bc/data.py` and `offline_grpo/data.py` for training-time reward computation. After fixing: SVAMP teacher accuracy = 92.6%, ASDiv = 86.6%.

## 3. Two-Stage Experiment: DG-Offline → Online GRPO (Alex's Idea)

Alex suggested trying a two-stage pipeline: first run DG-offline to improve the student's initialization, then continue with standard online GRPO. The intuition is that DG-offline shifts the student's greedy preference at branching points (our best offline result: 29.00% vs 27.16% baseline on MATH), which gives online GRPO a better starting point for reinforcing correct paths.

### Setup

Take the merged DG-offline η=0.5 checkpoint and run standard online GRPO on top of it. Fresh LoRA (r=32, α=32) on the merged model. Same hyperparameters as the baseline online GRPO result (32.10%).

### Status

| Job | Dataset | Starting model | Status |
|-----|---------|---------------|--------|
| 4681313 | MATH | DG-offline η=0.5 merged (29.00%) | Running |
| 4681314 | GSM8K | DG-offline η=0.5 merged (48.73%) | Running |

### What we're looking for

| Model | MATH greedy | GSM8K greedy |
|-------|-------------|-------------|
| Baseline (untrained) | 27.16% | 48.16% |
| DG-offline η=0.5 (stage 1 only) | 29.00% | 48.73% |
| Online GRPO from scratch | 32.10% | 55.82% (cross-task) |
| **DG-offline → Online GRPO** | **?** | **?** |

If the combined pipeline beats 32.10% on MATH, it means two-stage training is worth the extra compute. If it matches or falls short, online GRPO converges to the same place regardless of initialization.

## 5. DG-Mixture Prototype (Future Direction, Not Yet Approved)

Implemented a DG-Mixture trainer that runs online GRPO and DG-gated offline teacher loss in a single training step. This is a different approach from the two-stage pipeline: it combines both signals per gradient step rather than running them sequentially.

```
L_total = L_online (PPO clipped + KL on student) + λ · L_dg_teacher (gated REINFORCE, no KL)
```

Code: `mixture_grpo/dg_mixture/trainer.py`, `train.py`, `run_dg_mixture_math.sh`. Static smoke test passes. Full design doc at `docs/plans/dg_mixture_design.md`.

This is a prototype: not yet trained or tested, and several design questions remain open (which advantage baseline for teacher, where the gate applies, whether to position-weight early tokens). Waiting for mentor discussion before committing to a training run.
