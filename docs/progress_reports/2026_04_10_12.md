## 1. DG-Mixture Implementation

### What it is

A trainer that runs online student GRPO and DG-gated offline teacher loss in a single training step on the same batch of prompts. Combines the on-policy learning signal from online GRPO with the asymmetric filtering of DG-offline.

```
L_total = L_online (PPO clipped + KL on student) + λ · L_dg_teacher (gated REINFORCE, no KL)
```

Full design doc with architecture diagram preserved at `docs/plans/dg_mixture_design.md`.

### Implementation

Code: `mixture_grpo/dg_mixture/trainer.py` (DGMixtureGRPOTrainer), `mixture_grpo/dg_mixture/train.py`, `mixture_grpo/run_dg_mixture_math.sh`.

Key design choices:
- Forked from Method B's structure (separate online/offline loss terms)
- Teacher advantages use teacher-only group statistics (matches DG-offline's eta calibration)
- IS ratio neutralized on teacher side (same mechanism as DG-offline)
- KL penalty on student completions only (teacher is off-policy)
- Default hyperparameters: η=0.5, λ=0.3

Static smoke test passes. No results yet (pending training run).

## 2. Two-Stage Experiment: DG-Offline → Online GRPO

### Motivation

Mentor's question: "can we use grpo online and dg offline using the same batch? probably fine."

The two-stage approach is simpler than DG-Mixture: first train with DG-offline to improve the student's initialization, then continue with standard online GRPO. If DG-offline gives the student a better starting point (29.00% vs 27.16% baseline on MATH), online GRPO should find and reinforce correct paths more frequently from the start.

### Setup

| Parameter | Value |
|-----------|-------|
| Stage 1 model | DG-offline η=0.5 merged (29.00% greedy on MATH, 48.73% on GSM8K) |
| Stage 2 method | Standard online GRPO (same script as the 32.10% baseline result) |
| Fresh LoRA on merged DG-offline model | r=32, α=32, all-linear |
| MATH: 15 epochs, GSM8K: 15 epochs | Matching baseline online GRPO settings |

## 3. Unified Dataset Infrastructure

### The problem

Every time we added a new dataset, we had to modify 4+ training scripts (online GRPO, Mixture A, Mixture B, DG-Mixture) and their eval scripts. Each had hardcoded `if dataset_type == "math": ... else: ...` branches with dataset-specific imports.

### The solution

Created `shared/datasets_registry.py` — a single module where each dataset is registered with its HF path, field names, system prompt, answer extraction, reward function, and eval parameters. All training and eval scripts now import from this registry instead of hardcoding dataset logic.

Adding a new dataset is now:
1. One entry in `datasets_registry.py` (~15 lines)
2. Download to scratch cache
3. Generate rollouts: `DATASET=new sbatch shared/run_generate_rollouts.sh`
4. Train: `METHOD=bc DATASET=new sbatch shared/run_train_offline.sh`
5. Eval: `DATASET=new MODEL=/path sbatch shared/run_eval.sh`

No training script changes needed.

### Files in shared/

| File | Purpose |
|------|---------|
| `datasets_registry.py` | Dataset configs: math, gsm8k, svamp, asdiv |
| `eval_unified.py` | Greedy + best-of-N eval for any dataset |
| `generate_rollouts.py` | Teacher rollout generation for any dataset |
| `run_eval.sh` | SLURM wrapper for eval |
| `run_generate_rollouts.sh` | SLURM wrapper for rollout generation |
| `run_train_offline.sh` | SLURM wrapper for offline training (BC, Offline GRPO, DG-offline) |

### Bug found and fixed: teacher answer format mismatch

The 7B Math teacher outputs `\boxed{145}` even on numeric-answer datasets like SVAMP. Our `extract_numeric_answer` function looked for `####` and missed these. Initial rollout stats showed 14% teacher accuracy on SVAMP, which was clearly wrong.

Fix: `extract_numeric_answer` now tries three extraction methods in order: (1) `####` delimiter, (2) `\boxed{}`, (3) last number in text. After fixing, teacher accuracy on SVAMP = 92.6%, ASDiv = 86.6%.

The same fix was applied to `bc/data.py` and `offline_grpo/data.py` so training correctly identifies which teacher completions are correct.
