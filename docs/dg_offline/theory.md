# Recall: Delightful Policy Gradient (DG) and DG-Offline

Study notes for mentor briefing. Covers the original DG paper's motivation and mechanism, how we adapted it to our offline teacher-student setting (DG-offline), the implementation trick for neutralizing IS within TRL, why DG doesn't need teacher logprobs, and the practical implications for cross-model compatibility.

## 0. Equation Comparison: Three Methods Side by Side

### Shared notation

| Symbol | Name | Meaning |
|--------|------|---------|
| π_θ | Student policy | The model being trained. In our case Qwen2.5-0.5B-Instruct with LoRA adapters. π_θ(a_t \| s_t) is the probability the student assigns to token a_t given context s_t. |
| π_teacher | Teacher / behavior policy | The model that generated the offline completions. In our case Qwen2.5-Math-7B-Instruct. π_teacher(a_t \| s_t) is the probability the teacher assigned to token a_t when it generated the completion (stored during rollout generation). |
| π_ref | Reference policy | The unmodified base model, used as an anchor for the KL penalty. Obtained for free via LoRA's `disable_adapter()` — turning off the adapter recovers the original pretrained weights without loading a separate model. |
| a_t | Action at step t | The token at position t in the completion. |
| s_t | State at step t | The context (prompt + all tokens before position t) that the model conditions on to predict a_t. |
| R | Reward | Binary reward for the full completion: 1 if the extracted answer matches ground truth, 0 otherwise. |
| A | Advantage | GRPO group-normalized advantage: A = (R - μ_G) / σ_G, where μ_G and σ_G are the mean and std of rewards among the G completions generated for the same prompt. A single scalar shared by all tokens in the same completion. Positive = better than the group average, negative = worse. |
| r_t | Importance sampling (IS) ratio | r_t = π_θ(a_t \| s_t) / π_teacher(a_t \| s_t). Also called the importance weight or probability ratio. Measures how much more (or less) likely the student is to produce token a_t compared to the teacher. Used to correct for the distribution mismatch when learning from another policy's data. |
| clip(x, lo, hi) | PPO clipping | Clamps x to the range [lo, hi]. In our case clip(r_t, 1-ε, 1+ε) with ε=0.2, giving the range [0.8, 1.2]. The min(r_t × A, clip(r_t) × A) construction is the PPO clipped surrogate — it takes the more pessimistic (conservative) estimate to prevent excessively large policy updates. |
| KL(π_θ \|\| π_ref) | KL divergence penalty | Penalizes the student for drifting too far from the reference model. Keeps the student from forgetting its pretrained capabilities. Computed per-token using the approximation: exp(log π_ref - log π_θ) - (log π_ref - log π_θ) - 1. |
| β | KL coefficient | Scales the KL penalty. Higher β = more conservative (student stays closer to base model). β=0.1 for offline GRPO, β=0.01 for mixture methods. |
| ε | PPO clip range | Controls how far the IS ratio can deviate from 1.0 before clipping. ε=0.2 means the ratio is clamped to [0.8, 1.2]. |
| T | Completion length | Number of tokens in the completion (excluding padding). |
| S | Surprisal | How surprised the student is by a completion. Defined as the negative log-probability under the student's current policy: S = -log π_θ(a \| s). High surprisal = the student finds this unlikely. Measured in nats (using natural log). |
| χ (chi) | Delight | The product of advantage and surprisal: χ = A × S. Positive delight = a surprisingly good outcome. Negative delight = a surprisingly bad outcome. The core quantity in the DG method. |
| σ(x) | Sigmoid function | σ(x) = 1 / (1 + exp(-x)). Maps any real number to the range (0, 1). Used as the DG gate: σ(χ/η) produces a smooth 0-to-1 weight. |
| η (eta) | DG temperature | Controls the sharpness of the sigmoid gate. Small η = sharp gate (nearly binary 0 or 1, aggressive filtering). Large η = soft gate (values near 0.5, mild filtering). |
| m_t | Padding mask | 1 for real tokens, 0 for padding. Used to exclude padding tokens from mean surprisal calculation. |
| ∇ log π_θ(a_t) | Policy gradient | The gradient of the log-probability of token a_t w.r.t. the model parameters θ. This is the direction in parameter space that would increase the probability of producing a_t. Multiplied by the advantage (and any weighting) to form the REINFORCE gradient. |

### Standard Offline GRPO (IS-corrected)

Complete loss:

```
L = (1/T) Σ_t [ -min(r_t × A, clip(r_t, 1-ε, 1+ε) × A) ] + β × KL(π_θ || π_ref)
```

where:

```
r_t = π_θ(a_t | s_t) / π_teacher(a_t | s_t)            IS ratio at token t
```

The IS ratio π_θ/π_teacher corrects for the distribution mismatch: completions were generated by the teacher, but we want gradients as if they came from the student. PPO clipping constrains r_t to [0.8, 1.2] — if the student and teacher disagree too much on a token, the gradient for that token is zeroed out (the clipped path dominates and the min selects the conservative estimate).

Effective gradient (ignoring clipping):

```
∇L = -(π_θ / π_teacher) × A × ∇ log π_θ(a_t)  +  β × ∇KL
```

The gradient weight π_θ/π_teacher is **sign-blind**: it depends only on how likely both models find the token, not on whether the completion was correct (positive A) or incorrect (negative A). A surprising token gets the same IS weight regardless of the outcome.

### Original DG (Osband 2026, arXiv:2603.20521)

Complete loss:

```
L = -σ(χ / η) × A × log π_θ(a | s)
```

where:

```
χ = A × S                                               delight = advantage × surprisal
S = -log π_θ(a | s)                                     surprisal under learner's own current policy
```

The delight χ is the product of advantage and surprisal. Because advantage carries a sign (positive for success, negative for failure) and surprisal is always non-negative, delight is positive for surprising successes and negative for surprising failures. The sigmoid gate σ(χ/η) maps this to a 0-to-1 weight: ≈1 for surprising successes (learn from them), ≈0 for surprising failures (ignore them), ≈0.5 for unsurprising outcomes (mild update).

Effective gradient:

```
∇L = -σ(A × S / η) × A × ∇ log π_θ(a)
```

Setting:
- Behavior policy is a stale copy of the learner (same model, delayed D steps — small distribution gap)
- S is a scalar per episode (single action or short trajectory)
- No IS ratio, no behavior logprobs needed
- No KL penalty in the original paper (the gate itself regularizes by suppressing large updates on surprising samples)

### Our DG-Offline (adaptation to teacher-student offline RL)

Complete loss (as written in TRL's framework):

```
L = (1/T) Σ_t [ -min(r_t × A_gated, clip(r_t, 1-ε, 1+ε) × A_gated) ] + β × KL(π_θ || π_ref)
```

where:

```
s_t = -log π_θ(a_t | context_t)                          per-token surprisal under student
S = (1/T) Σ_t (s_t × m_t)                                mean surprisal over completion (m_t = padding mask)
χ = A × S                                                delight = advantage × mean surprisal
gate = σ(χ / η)                                          sigmoid gate
A_gated = gate × A                                       gated advantage (what we pass to TRL)

r_t = π_θ_new(a_t) / π_θ_current(a_t)                   IS ratio neutralized (see explanation below)
```

**IS neutralization trick**: We set old_logprobs = current_logprobs (the student's own logprobs right now, detached from the computation graph). At the start of each training step, π_θ_new and π_θ_current are the same model weights, so r_t = exp(same - same) = 1.0. Since clip(1.0, 0.8, 1.2) = 1.0, the PPO clipping is a no-op. This lets us work within TRL's fixed loss code without modifying it. The actual gradient weighting comes entirely from A_gated.

Because r_t ≈ 1.0, the loss simplifies to the effective form:

```
L ≈ (1/T) Σ_t [ -σ(A × S / η) × A × log π_θ(a_t) ] + β × KL(π_θ || π_ref)
```

Effective gradient:

```
∇L = -σ(A × S / η) × A × ∇ log π_θ(a_t)  +  β × ∇KL
```

This matches the original DG paper's Equation 1, plus a KL penalty term.

Key differences from the original DG:
- **Surprisal aggregation**: S is the mean of per-token surprisals across the completion, not a single per-episode value. Mean (not sum) normalizes for completion length — without this, longer completions would have systematically higher surprisal and more extreme gates, biasing training toward shorter completions.
- **KL penalty**: Added because the gate alone may not prevent excessive drift in the large 7B→0.5B distribution gap. The original paper's setting (stale self-play with small gap) didn't need it.
- **PPO clipping**: Structurally present but neutralized at the start of each step. If num_ppo_epochs > 1, the model weights update within mini-batches, causing r_t to drift from 1.0 — PPO clipping then re-engages as a trust region, which is desirable.

### Side by side: what goes into the gradient weight

```
Offline GRPO:    weight = π_θ(a_t) / π_teacher(a_t)          ← needs π_teacher, sign-blind
Original DG:     weight = σ(A × S / η)                        ← needs only π_θ (via S), sign-aware
Our DG-Offline:  weight = σ(A × mean_t(-log π_θ(a_t)) / η)   ← needs only π_θ, sign-aware, length-normalized
```

- **Sign-blind** means the weight depends only on the action probabilities, not on whether the outcome was good or bad. IS gives the same weight to a surprising success and a surprising failure.
- **Sign-aware** means the weight depends on the product of advantage (signed) and surprisal (unsigned), so the gate distinguishes surprising successes (amplified) from surprising failures (suppressed).

### What each method requires from the teacher

| | Standard Offline GRPO | Original DG | Our DG-Offline |
|---|---|---|---|
| Teacher completion text | Yes | N/A (same model) | Yes |
| Teacher per-token logprobs | **Yes** (for IS ratio denominator) | N/A | **No** |
| Reward / correctness label | Yes | Yes | Yes |
| Same tokenizer as student | **Yes** (token-level ratio needs aligned token IDs) | N/A | **No** (only needs text; can re-tokenize with student's tokenizer) |
| Student forward pass | Yes (for IS ratio numerator and KL) | Yes (for surprisal) | Yes (for surprisal and KL) |

### Key differences at a glance

| Property | Offline GRPO | Original DG | Our DG-Offline |
|----------|-------------|-------------|----------------|
| Distribution gap | Any (corrected by IS) | Small (stale self-play) | Large (7B→0.5B cross-model) |
| Gradient weight | π_θ/π_teacher (sign-blind) | σ(A×S/η) (sign-aware) | σ(A×S/η) (sign-aware) |
| Surprisal scope | N/A (uses IS ratio instead) | Per-episode scalar | Mean per-token over completion |
| Surprising failure | Same weight as success | Suppressed (gate→0) | Suppressed (gate→0) |
| Surprising success | Same weight as failure | Amplified (gate→1) | Amplified (gate→1) |
| Unsurprising outcome | Weight depends on ratio | Gate ≈ 0.5 (mild update) | Gate ≈ 0.5 (mild update) |
| Teacher logprobs needed | Yes | No | No |
| KL penalty | Yes (β × KL) | No | Yes (β × KL) |

## 1. The Problem DG Solves

### 1.1 Off-policy learning needs correction

In online GRPO, the student generates its own completions. The policy gradient is:

```
∇L = E_{a ~ π_student} [advantage(a) × ∇ log π_student(a)]
```

The expectation is over the student's own distribution — the gradient is unbiased.

In offline GRPO, completions come from the teacher:

```
∇L = E_{a ~ π_teacher} [advantage(a) × ∇ log π_student(a)]
```

This is biased. The samples are drawn from what the teacher tends to do, not what the student tends to do. The student gets a skewed view of the world — teacher-favored strategies are overrepresented, student-favored strategies are underrepresented.

### 1.2 The standard fix: Importance Sampling (IS)

IS reweights each sample to correct the bias:

```
E_{a ~ π_student}[f(a)] = E_{a ~ π_teacher}[(π_student(a) / π_teacher(a)) × f(a)]
```

The ratio π_student / π_teacher adjusts each sample:
- ratio > 1: The student would produce this more often than the teacher did → upweight (underrepresented in teacher data)
- ratio < 1: The student would produce this less often → downweight (overrepresented)
- ratio = 1: Both equally likely → no correction needed

### 1.3 Why IS fails in our setting

For a 500-token completion, the sequence-level IS ratio is a product of per-token ratios:

```
ratio = ∏_{t=1}^{500} π_student(token_t) / π_teacher(token_t)
```

If even one token has a 10x ratio and another has 0.01x, the product swings wildly. Over hundreds of tokens, ratios either explode (10^20) or collapse (10^-250). PPO clipping truncates them to [0.8, 1.2], but clipped tokens contribute zero gradient — wasted compute.

More fundamentally, IS is **sign-blind**: the ratio π_student(a) / π_teacher(a) depends only on the action, not the reward. Two completions the student finds equally surprising get the same IS weight regardless of whether one was correct and the other wrong.

## 2. The Original DG (Osband 2026)

Reference: Osband (2026), "Delightful Distributed Policy Gradient", arXiv:2603.20521

### 2.1 Core idea: Delight

Instead of IS ratios, DG defines a scalar called **delight**:

```
delight = advantage × surprisal
```

where:
- advantage = how much better/worse this outcome was than the group average
- surprisal = -log π_learner(action) = how unexpected this action is under the learner's **own** current policy

The gradient weight is a sigmoid gate:

```
gate = σ(delight / η)
```

where η is a temperature controlling gate sharpness.

### 2.2 The four quadrants — the key insight

The gate produces asymmetric behavior based on the sign combination of advantage and surprisal:

```
                  High surprisal                    Low surprisal
                  (student wouldn't do this)        (student already does this)
              ┌────────────────���───────────────┬─────────────────────���──────────┐
  Positive    │ delight = large positive       │ delight = small positive       │
  advantage   │ gate ≈ 1                       │ gate ≈ 0.5                     │
  (correct)   │ "Learn this! A correct         │ "You already know this,        │
              │  strategy you haven't found"   │  mild reinforcement"           │
              ├────────────────────────────────┼────────────────────────────────┤
  Negative    │ delight = large negative       │ delight = small negative       │
  advantage   │ gate ≈ 0                       │ gate ≈ 0.5                     │
  (wrong)     │ "Ignore. You'd never           │ "You do this and it's wrong —  │
              │  do this anyway"               │  learn to stop"                │
              └──────────────���─────────────────┴────────────────────────────────┘
```

The theoretical result (Proposition 3 in the paper): **no IS-based reweighting can reproduce this asymmetry.** IS weights f(a) = π(a)/μ(a) are functions of the action alone — they cannot distinguish "surprising success" from "surprising failure" because both have the same action probability. Delight can, because it is the product of advantage (sign-dependent) and surprisal.

### 2.3 Original paper's setting

The paper was designed for a simpler scenario than ours:

| Aspect | Original paper | Our setting |
|--------|---------------|-------------|
| Behavior policy | Same model, delayed D steps | 7B teacher (different model) |
| Learner | Same architecture as behavior | 0.5B student (14x smaller) |
| Distribution gap | Small (stale checkpoint) | Enormous (cross-model, cross-capacity) |
| Actions | Single token or short sequences | 500+ token completions |
| Advantage | Binary (±0.5) or shaped reward | GRPO group-normalized |

## 3. Our Adaptation: DG-Offline

### 3.1 Surprisal aggregation

The paper has one surprisal per episode. We have 500+ tokens per completion. We take the mean per-token surprisal:

```
completion_surprisal = mean(-log π_student(token_t))  over completion tokens
```

Why mean, not sum: sum would bias toward longer completions (more tokens = higher surprisal = more extreme gate), making training prefer shorter completions regardless of quality.

### 3.2 No behavior logprobs needed

Standard offline GRPO requires teacher per-token logprobs stored during rollout generation. DG computes everything from the learner's current policy — surprisal is -log π_student, not -log π_teacher. The teacher's logprobs are never used.

### 3.3 The η parameter

η controls how decisive the gate is:
- Small η (e.g. 0.1): Sigmoid is very sharp. Gate is nearly binary (0 or 1). Aggressive filtering.
- Large η (e.g. 2.0): Sigmoid is soft. Gate stays near 0.5 for most samples. Mild filtering.

Our results: η=0.5 is best on MATH (pass@16: 64.2%), η=1.0 is best on GSM8K (pass@16: 85.67%). The optimal η depends on the dataset's surprisal distribution.

## 4. Implementation: Neutralizing IS Within TRL (Step 6)

### 4.1 The problem

TRL's `GRPOTrainer._compute_loss` hardcodes PPO-style clipped loss:

```python
ratio = exp(new_logprobs - old_logprobs)
clipped_ratio = clip(ratio, 1-ε, 1+ε)
loss = -min(ratio × advantage, clipped_ratio × advantage)
```

We cannot remove this — it is baked into TRL. But DG wants pure gated REINFORCE with no IS ratio.

### 4.2 The trick

Set `old_logprobs` to the student's **current** logprobs:

```python
old_per_token_logps = current_per_token_logps.detach()
```

Then TRL computes:

```
ratio = exp(new_logprobs - current_logprobs)
```

At the start of each training step, `new` and `current` are the same model weights:

```
ratio = exp(same - same) = exp(0) = 1.0
clip(1.0, 0.8, 1.2) = 1.0  → clipping is a no-op
```

The loss simplifies to:

```
loss = -1.0 × gated_advantage × (per-token loss terms)
```

Which is exactly gated REINFORCE. We got what we wanted without modifying TRL's code.

### 4.3 Why .detach() matters

`.detach()` means "treat this tensor as a constant — do not backpropagate through it." Without it, gradients would flow through `old_logprobs` into the model, changing the loss in unintended ways. The paper treats the gate as a fixed weight, not a differentiable function of the policy.

### 4.4 Side-by-side comparison of what old_logprobs is set to

| Method | old_per_token_logps = | Resulting ratio | Purpose |
|--------|----------------------|-----------------|---------|
| Online GRPO | π_student at generation time | π_new / π_old_student | Trust region (don't update too far per step) |
| Offline GRPO | π_teacher from rollout files | π_student / π_teacher | IS correction (reweight teacher data to look like student data) |
| DG-offline | π_student right now (.detach()) | π_new / π_current ≈ 1.0 | Neutralized (gate replaces IS) |

### 4.5 What happens with num_ppo_epochs > 1

Within PPO mini-batches, the model weights update, causing `new` to drift from the `current` snapshot. The ratio deviates from 1.0, and PPO clipping engages. This is actually desirable — it prevents the model from taking too-large steps within a single outer step, providing a trust region even though the inter-step IS is neutralized.

## 5. Why DG Does Not Need Teacher Logprobs

### 5.1 The gradient comparison

Offline GRPO gradient:
```
∇L = -(π_student / π_teacher) × advantage × ∇ log π_student
      ^^^^^^^^^^^^^^^^^^^^^^^^
      IS ratio — needs π_teacher at every token position
```

DG-offline gradient:
```
∇L = -σ(advantage × surprisal / η) × advantage × ∇ log π_student
      ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
      gate — every term comes from the student or the reward
```

Unpacking what is inside the gate:
- `advantage`: computed from rewards (did the answer match ground truth?). No logprobs involved.
- `surprisal`: -log π_student(completion). The student's own forward pass on the teacher's text.
- `η`: a hyperparameter.

No term involves π_teacher. The gate asks "is this a surprising success or surprising failure **from the student's perspective**?" It does not ask how likely the teacher thought this completion was.

### 5.2 The philosophical difference

IS and DG solve the same problem (off-policy correction) with different philosophies:

**IS asks**: "How different is this sample from what the student would generate?"
→ Compare both policies' probabilities on the same completion → needs both π_student AND π_teacher.

**DG asks**: "Should the student learn from this sample?"
→ Is it a good outcome (advantage) that the student doesn't already know (surprisal)?
→ Both signals come from the student's own policy and the reward. The teacher's confidence is irrelevant.

Concretely: if the teacher solves a problem using a clever factoring trick with 85% confidence per token, and the student assigns 5% to the same token:
- IS: ratio = 0.05/0.85 = 0.06 → downweight heavily. "Student wouldn't do this, so discount it."
- DG: surprisal = -log(0.05) = 3.0, positive advantage → high delight → gate ≈ 1. "Student doesn't know this yet and it works — learn from it."

### 5.3 What DG still needs from the teacher

DG does not need teacher logprobs, but still needs:

1. **The teacher's completion text/tokens**: the actual sequence the teacher generated, so the student can run a forward pass on it and compute its own logprobs.
2. **The reward**: did the teacher's completion get the right answer? Computed by checking `\boxed{...}` against ground truth, not from any model probability.

The teacher contributes **what it said** (text) and **whether it was right** (reward). Not **how confident it was** (logprobs).

### 5.4 Practical implication: DG enables black-box teachers

Because DG does not need per-token logprobs from the behavior policy, you could use completions from a black-box API (e.g. GPT-4, Claude) where logprobs are unavailable or limited. All you need is the text output and a way to check correctness. This is impossible with IS-based offline GRPO.

## 6. Cross-Model Compatibility: DG is teacher-agnostic

### 6.1 Headline

DG-offline only needs the **student** to be able to consume the text. The teacher contributes a string and a reward. Tokenizer, architecture, vocab size, and even logprob availability of the teacher are all irrelevant to the gate.

This is the central capability difference between DG-offline and Offline-GRPO:

| Requirement | Offline-GRPO (IS) | DG-offline |
|---|---|---|
| Teacher logprobs at every token | **Required** | Not used |
| Teacher tokenizer = student tokenizer | **Required** (token IDs must align) | Not required |
| Teacher token IDs mean the same strings as student token IDs | **Required** | Not required |
| Teacher is callable (logprobs accessible) | **Required** | Not required (text-only API works) |

If any of the first three fails for Offline-GRPO, the IS ratio is mathematically undefined — not just inaccurate, but nonsensical. DG sidesteps all four by computing surprisal under the student's own policy on the student's own re-tokenization of the teacher's text.

### 6.2 Why IS needs all four

IS computes π_student(token_t) / π_teacher(token_t) at every position:

1. **Same tokenization**: both models must tokenize the same text into the same token sequence. If "1024" becomes `["1024"]` in one model and `["10", "24"]` in another, there is no token-level alignment.
2. **Same token ID mapping**: token ID 5832 must mean the same string in both models. Otherwise you are dividing the probability of "apple" by the probability of "banana."
3. **Teacher logprobs available**: the ratio's denominator does not exist for closed-API teachers without logprob endpoints.

DG's gate σ((advantage × surprisal_under_student) / η) does not depend on any of these.

### 6.3 The cross-tokenizer recipe (the general case)

For an arbitrary teacher with a different tokenizer, vocab, or even just text-only output (e.g., GPT-4, Claude, a different-family open model):

- Take the teacher's completion as **text**.
- Re-tokenize the text with the **student's** tokenizer.
- Student runs forward pass on its own token IDs → computes surprisal.
- DG gate works normally.

The only requirement is that the student can consume the text, not the token IDs. This makes DG suitable for cross-architecture offline RL where IS is not even definable.

### 6.4 Aside: the 128-row Qwen2.5 corner case

Our current rollout pipeline shares `offline_grpo/data.py` between Offline-GRPO and DG-offline. That loader stores teacher rollouts as pre-tokenized `completion_ids` and is therefore subject to the Qwen2.5 vocab mismatch:

| Model | Vocab size |
|-------|-----------|
| Student (Qwen2.5-0.5B-Instruct) | 151,936 |
| Teacher (Qwen2.5-Math-7B-Instruct) | 152,064 |
| Difference | 128 extra tokens in teacher |

Both share the same base tokenizer for IDs 0-151,935. The teacher has 128 extra special tokens (151,936-152,063). The loader truncates at the first out-of-student-vocab ID (`offline_grpo/data.py` lines 40-46) so the student's embedding matrix can do the lookup. Affects ~0.003% of tokens.

This truncation is a property of the **shared loader**, not of DG. DG-offline inherits it today only because we reuse `load_rollouts` from the offline-GRPO data path. A loader that stores teacher output as text and re-tokenizes under the student tokenizer at training time has no such constraint — the IDs are the student's own and there are no out-of-vocab IDs to truncate. Implementing that string-input loader is the small lift required to exercise DG's full teacher-agnosticism in our codebase; it is the prerequisite for the planned multi-teacher experiment ([`plans/multi_teacher_experiment.md`](plans/multi_teacher_experiment.md)).

## 7. Numerical Walkthrough

### 7.1 Two completions for "What is 2^10?"

**Completion 1** — teacher correct, advantage = +0.8:
- Text: "2^10 = 1024. The answer is \boxed{1024}."
- Student mean surprisal: 1.2 (student mostly agrees, knows powers of 2)

```
delight  = +0.8 × 1.2 = +0.96
gate     = σ(0.96 / 0.5) = σ(1.92) = 0.872
gradient = 0.872 × 0.8 = 0.698  ← strong positive, student learns from this
```

**Completion 2** — teacher wrong, advantage = -0.8:
- Text: "Using logarithms, ln(2^10) = 10 ln 2 ≈ 6.93, so 2^10 ≈ e^6.93 ≈ 1020."
- Student mean surprisal: 4.5 (student finds this logarithm approach very surprising)

```
delight  = -0.8 × 4.5 = -3.6
gate     = σ(-3.6 / 0.5) = σ(-7.2) = 0.00075
gradient = 0.00075 × (-0.8) = -0.0006  ← nearly zero, student ignores this
```

IS comparison: both completions have high surprisal → both get large IS ratios. Completion 2 gets a large negative gradient pushing the student away from a strategy it would never use anyway — wasted gradient. DG suppresses it to near-zero.

Teacher completion: "The answer is \boxed{255}." (6 tokens)

| "The" | 0.70 | 0.60 | 0.86 | surprisal = 0.51 |
| "answer" | 0.80 | 0.40 | 0.50 | surprisal = 0.92 |
| "is" | 0.90 | 0.85 | 0.94 | surprisal = 0.16 |
| "\boxed" | 0.95 | 0.02 | 0.02 | surprisal = 3.91 |
| "{255" | 0.88 | 0.10 | 0.11 | surprisal = 2.30 |
| "}" | 0.99 | 0.95 | 0.96 | surprisal = 0.05 |

IS sequence ratio = 0.86 × 0.50 × 0.94 × 0.02 × 0.11 × 0.96 = **0.00085**
→ Clipped per-token, "\boxed" token ratio (0.02) clips to 0.8 → zero gradient for that token.

DG mean surprisal = mean(0.51, 0.92, 0.16, 3.91, 2.30, 0.05) = **1.31**
→ With advantage = +0.8: delight = 1.05, gate = σ(2.10) = 0.891 → healthy gradient.

The "\boxed" token that killed IS is just one contributor to DG's mean surprisal. It raises the surprisal (making the gate stronger for a correct completion) rather than collapsing the entire gradient to zero.

## 8. Summary

| Property | IS (Offline GRPO) | DG (DG-Offline) |
|----------|-------------------|-----------------|
| Gradient weight | π_student / π_teacher, PPO-clipped | σ(advantage × surprisal / η) |
| Needs teacher logprobs | Yes, at every token | No |
| Surprising success handling | Downweighted (low ratio) | Amplified (gate ≈ 1) |
| Surprising failure handling | Downweighted (low ratio) — same as success | Suppressed (gate ≈ 0) |
| Zero-advantage completions | Zero gradient | Gate = 0.5 (half-strength signal) |
| Robustness to logprob noise | Sensitive (ratio amplifies errors) | Immune (teacher logprobs unused) |
| Cross-tokenizer compatibility | Requires same tokenizer | Only needs student to consume the text |
| Per-sample compute | 1 forward pass | 1 forward pass (same cost) |
| Theoretical backing | Unbiased under exact ratio (biased when clipped) | Proposition 3: provably cannot be replicated by any IS scheme |
